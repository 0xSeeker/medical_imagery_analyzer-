**Take a medical scan, hide who the patient is, and let an AI assistant (Gemini, ChatGPT or Claude) describe what it sees in a structured written report.**

> [!WARNING]
> **Medical Disclaimer:** The outputs generated by this project are produced by an Artificial Intelligence model. They are strictly for educational, informational, and research purposes. The generated reports **DO NOT** constitute professional medical advice, diagnosis, or treatment. Always consult a certified medical professional or radiologist regarding any health-related conditions. Ensure you comply with HIPAA, GDPR, or local healthcare data privacy laws before uploading any data to a third-party API.

> [!NOTE]
> **Testing status:** Extended testing has **only been performed with Google Gemini** (the default provider). The OpenAI and Anthropic integrations are implemented against their official SDKs but have not been extensively tested. Expect possible rough edges (model names, image size limits, reasoning options) and please open an issue if you run into one.

## 🧒 In plain words

*No medical or technical background needed for this part.*

### What is this?

When you have a scan (an X-ray, a CT, an MRI...), the file that comes out of the hospital machine contains the pictures **and** a lot of personal details: the patient's name, birth date, ID number, the hospital, the doctor's name, and so on.

This project is a small "assembly line" that:

1. **Removes the personal details** from the scan file,
2. **Lets you check** that they are really gone,
3. **Turns the scan into ordinary pictures** and asks an **AI assistant** to look at them and write a report.

### The 3 steps, simply

| Step | What happens | Think of it as... |
|------|--------------|-------------------|
| 🧽 **1. Hide who the patient is** | The program wipes names, IDs, birth dates, hospital details... from the scan file. | Blacking out the name on a paper document before sharing it. |
| 🔎 **2. Double-check** | A second program shows a "before / after" table so you can see those details are gone. | Re-reading the document to make sure nothing was missed. |
| 🖼️ → 🤖 **3. Pictures + AI report** | The scans are saved as normal pictures, sent to an AI, which writes a report: what it sees, what it might mean, and what to do next. | Asking a very well-read assistant to describe the images and summarize them. |

### What does the report look like?

Every report follows the same layout, so they are easy to compare:

- a **step-by-step description** of each image,
- a **comparison** between images of the same exam,
- a **final report** with findings, recommendations, and an **"Impression" written in everyday language** that a patient without medical knowledge can understand,
- the AI's **"thinking"** section, so you can see how it got there (when the AI provides it).

### Mini glossary

| Word | What it means here |
|------|--------------------|
| **DICOM** (`.dcm`) | The special file format used by hospital scanners. Think of a photo with a hidden label attached that holds the patient's details. |
| **Anonymize** | Remove or blank out the details that identify the patient. |
| **PNG** | A normal picture file, openable anywhere (like a photo). |
| **AI model** | The "assistant" that looks at the pictures: Gemini (Google), ChatGPT (OpenAI) or Claude (Anthropic). |
| **API key** | A personal password that lets the program talk to the AI company's service. Keep it private. |
| **Report** | The text file (`.md`) the AI writes for each exam. |

### Who is it for?

Students, researchers, and curious developers who want to experiment with AI reading medical images.

**It is not for** getting a diagnosis or making medical decisions. An AI can be wrong, can miss things, and can sound very sure while doing so. Always rely on a real doctor.

### Two things to keep in mind

- 🔐 **The pictures leave your computer.** To be analyzed, they are sent to the AI company's servers. Only use data you are allowed to share.
- 🧽 **Anonymization here is basic, not a guarantee.** It clears the most common identity fields (listed [below](#how-the-anonymization-works)) but it is not a certified, complete de-identification. See [Known Limitations](#-known-limitations).

## ✨ Features

### 🛡️ Anonymization & Verification (`Dicomanon/`)
- **Identity scrubbing:** Clears or overrides common personal-information fields (patient name, ID, birth date, institution, physicians...).
- **Private tag removal:** Strips the manufacturer-specific hidden fields that scanners add and that may contain identifying data.
- **Verification tool:** Compares the original and anonymized files side by side in a terminal table and prints a clear SUCCESS / FAILED result.

#### How the anonymization works

For these fields: `PatientName`, `PatientID`, `PatientBirthDate`, `PatientSex`, `PatientAge`, `PatientWeight`, `PatientAddress`, `InstitutionName`, `InstitutionAddress`, `ReferringPhysicianName`, `PerformingPhysicianName`, `StudyID`, `AccessionNumber`, `OtherPatientIDs`, `StudyDescription`, `SeriesDescription`:

- **Names** (patient and physicians) are replaced by `ANONYMOUS`.
- **All other fields** in the list are emptied.
- **Private (manufacturer) tags** are removed.

The verification script checks exactly the same list, plus the presence of private tags.

### 🖼️ Automated Conversion
- **Batch processing:** Recursively scans a folder and converts every `.dcm` scan into `.png` pictures.
- **Multi-frame scans:** Scans made of several slices (3D/multi-frame) are split into individual pictures that stay grouped together.
- **Image optimization:** Applies the contrast settings stored in the file (VOI LUT) and handles inverted grayscale (MONOCHROME1) so images look right.

### 🤖 AI-Powered Medical Analysis
- **Multi-provider:** Choose between Google Gemini, OpenAI (ChatGPT) and Anthropic Claude with a single `--provider` flag. Gemini remains the default.
- **Advanced AI reasoning:** Uses each provider's reasoning feature (Gemini *Thinking*, Anthropic *extended thinking*, OpenAI *reasoning summaries*) to emulate step-by-step reasoning.
- **Grouped context:** Pictures coming from the same original scan are analyzed together for comparison.
- **Structured reporting:** Outputs Markdown (`.md`) reports including the AI's reasoning, visual findings, clinical impression, and recommendations. Each report states which provider and model produced it.
- **Command-line control:** Choose inputs, outputs, provider, model, and API key through flags.

## 🔌 Supported AI Providers

| Provider | `--provider` | Default model | API key env variable | Package to install | Test status |
|----------|--------------|---------------|----------------------|--------------------|-------------|
| Google Gemini | `gemini` (default) | `gemini-2.5-pro` | `GEMINI_API_KEY` | `google-genai` | ✅ Extensively tested |
| OpenAI (ChatGPT) | `openai` | `gpt-5` | `OPENAI_API_KEY` | `openai` | ⚠️ Not extensively tested |
| Anthropic Claude | `anthropic` | `claude-sonnet-5-5` | `ANTHROPIC_API_KEY` | `anthropic` | ⚠️ Not extensively tested |

Only the package of the provider you actually use needs to be installed. You can use any image-capable model of a given provider with `-m`.

How the AI's "thinking" is reported differs by provider:

- **Gemini:** thought parts returned by the API.
- **Anthropic:** thinking blocks returned by the API.
- **OpenAI:** only a reasoning *summary* is available (the raw reasoning is not exposed).

If a model does not support these options, the pipeline retries without them and the report shows "No internal reasoning returned."

```
.
├── Dicomanon/
│   ├── DicomAnon.py                 # Anonymizes one scan file (clears identity fields, removes private tags)
│   └── DicomVerifAnon.py            # Compares original vs anonymized file and reports the result
├── Pipeline_dicom_analyzer.py       # Converts scans to pictures + multi-provider AI analysis
```

## 🛠️ Installation

1. **Clone the repository:**
   ```bash
   git clone https://github.com/0xSeeker/medical_imagery_analyzer-.git
   cd medical_imagery_analyzer-
   ```

2. **Create a virtual environment (Recommended):**

   ```bash
   python -m venv venv
   source venv/bin/activate  # On Windows use: venv\Scripts\activate
   ```

3. **Install the core dependencies:**

   ```bash
   pip install numpy pydicom Pillow
   ```

4. **Install the package for the AI provider(s) you want to use:**

   ```bash
   pip install google-genai   # Gemini (default)
   pip install openai         # OpenAI / ChatGPT
   pip install anthropic      # Anthropic Claude
   ```

## 🚀 Usage Workflow

All scripts use command-line parameters. You can add `-v` or `--verbose` to any command for detailed logs.

### 1. Hide the patient's identity (anonymize)

Before analyzing any patient data, it **must** be anonymized. The script works on **one file at a time**: pass the original file and where to save the anonymized copy (the destination folder is created if needed).

```bash
python Dicomanon/DicomAnon.py -i Dicom_Input/patient.dcm -o Dicom_Output/patient.dcm -v
```

To process a whole folder (Linux/macOS):

```bash
for f in Dicom_Input/*.dcm; do
  python Dicomanon/DicomAnon.py -i "$f" -o "Dicom_Output/$(basename "$f")"
done
```

### 2. Double-check (verify)

Compare an original file with its anonymized copy:

```bash
python Dicomanon/DicomVerifAnon.py -orig Dicom_Input/patient.dcm -anon Dicom_Output/patient.dcm
```

You will see a side-by-side table of the checked fields and a final **SUCCESS** or **FAILED** message. A field is flagged if the original had a value and the anonymized copy still has something other than empty or `ANONYMOUS`; remaining private tags are flagged too.

### 3. Convert & AI Analysis

Once files are anonymized, point the pipeline to them. It converts the scans to pictures, then sends them to the AI provider you choose.

**Gemini (default):**

```bash
python Pipeline_dicom_analyzer.py \
    -i Dicom_Output \
    -p png_output \
    -r Reports \
    -m gemini-2.5-pro \
    -v
```

**OpenAI (ChatGPT):**

```bash
python Pipeline_dicom_analyzer.py -i Dicom_Output -p png_output -r Reports --provider openai -m gpt-5 -v
```

**Anthropic Claude:**

```bash
python Pipeline_dicom_analyzer.py -i Dicom_Output -p png_output -r Reports --provider anthropic -m claude-sonnet-5-5 -v
```

**Available Pipeline Flags:**

* `-i`, `--input`: Folder containing the (anonymized) scan files (default: `Pipeline_dcm_analyzer/dicom_input`)
* `-p`, `--png-output`: Folder where the converted pictures are saved (default: `Pipeline_dcm_analyzer/png_output`)
* `-r`, `--report-output`: Folder where the Markdown reports are saved (default: `Pipeline_dcm_analyzer/reports`)
* `--provider`: AI provider to use: `gemini`, `openai` or `anthropic` (default: `gemini`)
* `-k`, `--api-key`: API key for the selected provider (defaults to `GEMINI_API_KEY`, `OPENAI_API_KEY` or `ANTHROPIC_API_KEY` depending on `--provider`)
* `-m`, `--model`: Model ID (defaults to `gemini-2.5-pro`, `gpt-5` or `claude-sonnet-5-5` depending on `--provider`)
* `-v`, `--verbose`: Enable detailed processing logs.

## ⚙️ Configuration

> [!IMPORTANT]
> **Never commit your API keys to GitHub!**

You need a valid API key for the provider you select. Instead of using the `-k` flag (which can end up in your terminal history), it is highly recommended to set it as an environment variable:

```bash
# On Linux/macOS
export GEMINI_API_KEY="your_api_key_here"
export OPENAI_API_KEY="your_api_key_here"
export ANTHROPIC_API_KEY="your_api_key_here"

# On Windows (Command Prompt)
set GEMINI_API_KEY=your_api_key_here
set OPENAI_API_KEY=your_api_key_here
set ANTHROPIC_API_KEY=your_api_key_here

# On Windows (PowerShell)
$env:GEMINI_API_KEY="your_api_key_here"
$env:OPENAI_API_KEY="your_api_key_here"
$env:ANTHROPIC_API_KEY="your_api_key_here"
```

You only need to set the variable for the provider you use. The script detects it automatically if `-k` is not provided.

## ⚠️ Known Limitations

- **Testing coverage:** extended testing has only been done with Gemini. OpenAI and Anthropic support is newer and less battle-tested.
- **Anonymization is basic, not certified.** Only the 16 fields listed [above](#how-the-anonymization-works) are cleared, plus private tags. Other information that can identify someone is **not** touched, for example:
  - exam dates and times,
  - unique identifiers stored in the file (study/series/instance UIDs),
  - other descriptive fields (device, station or operator names, free-text comments...),
  - **text written directly on the image** (for example a name or date burned into the picture), which is also sent to the AI as part of the pictures.

  The verification script checks only the same list of fields, so it cannot detect what the anonymizer does not handle. Review your files before sharing them, and use a full de-identification tool if you need compliance with a specific regulation.
- **One file at a time:** the anonymization and verification scripts handle a single file per run (see the folder example above).
- **Image limits:** each provider limits the number and size of images per request (for example, Anthropic accepts up to 100 images and 5 MB per image). Large multi-frame series (CT/MRI) may exceed these limits and require downscaling or frame sampling.
- **Model names:** default model IDs may change over time. Use `-m` to select a model available on your account.
- **Reasoning output:** the level of detail of the AI's "thinking" depends on the provider (see [Supported AI Providers](#-supported-ai-providers)).
- **Privacy:** pictures are sent to the selected third-party AI service. Make sure your use complies with local regulations and with the provider's terms.
